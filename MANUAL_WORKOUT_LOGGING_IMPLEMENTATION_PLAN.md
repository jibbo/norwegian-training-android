# Norwy Manual Workout Logging
## Developer Blueprint and Incremental Implementation Plan

> Status: planning document only. No source implementation is included here.
>
> Feature area: `LogActivity`
>
> Goal: let users silently record an external workout for streak purposes without changing Norwy progression or introducing a visible manual-workout history yet.

---

## 1. Product contract

### 1.1 User flow

1. User opens `LogActivity`.
2. User taps a `+` action in the top app bar.
3. A dark Material 3 modal bottom sheet opens.
4. User selects exactly one workout type.
5. User chooses a date.
6. User enters a duration as separate two-digit hour and minute fields.
7. User taps Save.
8. If valid, the manual workout is stored, streak state is updated through the existing session data, the analytics event is emitted, and the sheet closes.
9. The saved manual workout is not displayed in the LogActivity history in this iteration.

### 1.2 Supported workout types

Display exactly this list, in this order:

1. 👟 Run
2. 🏋️ Strength training
3. 🚲 Cycling
4. 🏊 Swimming
5. 👣 Walking
6. ⏱️ HIIT

The labels are localized string resources. The selected translated text is persisted as `Session.name`; it is not retranslated when the app locale later changes.

### 1.3 Date rules

- Default: today.
- Minimum: January 1 of the current year.
- Maximum: today.
- Future dates are forbidden.
- A past date may be selected and immediately affects streak calculations.
- Use the existing `Session`/`Date` persistence convention.
- Display the date using the localized date format.

### 1.4 Duration rules

Render:

```text
HH : MM
```

- Hours and minutes are separate numeric text fields.
- The colon is fixed UI text.
- Both fields use a numeric keyboard.
- Each field accepts exactly two digits.
- Default: `01:00`.
- Valid range: `00:01` through `24:00`.
- `24:00` is valid.
- Anything greater than `24:00` is invalid.
- `00:00` is invalid.
- Duration is persisted as total minutes in a non-null `Long`.

Examples:

```text
00:01 -> 1L
01:00 -> 60L
01:30 -> 90L
23:59 -> 1439L
24:00 -> 1440L
24:01 -> invalid
```

### 1.5 Form behavior

- No workout type is preselected.
- Save remains enabled even when input is invalid.
- Save validation displays field-specific errors and keeps the sheet open.
- Entered values remain after validation errors.
- While saving, Save is disabled and shows a loading state.
- Database failure keeps the sheet open, preserves all values, exits loading state, and displays a retryable error.
- Tapping outside or pressing Back dismisses the sheet immediately without saving.
- Reopening starts a fresh form with no type, today’s date, and `01:00`.
- No edit or delete functionality is included.
- Multiple manual workouts may be saved for the same date and type.

### 1.6 Persistence semantics

Extend the existing `Session` entity. Do not create a separate manual-workout table.

New fields:

```kotlin
isManual: Boolean
name: String
 duration: Long
```

Existing and manual rows:

| Field | Existing Norwy session | New manual session |
|---|---:|---:|
| `id` | preserved/autogenerated | autogenerated |
| `phasesEnded` | preserved | `1` |
| `skipCount` | preserved | `0` |
| `date` | preserved | selected date |
| `isManual` | `false` | `true` |
| `name` | migrated to `"HIIT"` | selected translated label |
| `duration` | migrated to `0L` | total minutes |

### 1.7 Streak and progression behavior

Manual sessions:

- Count as an active streak day on their selected date.
- Recalculate streaks retroactively for past dates.
- Count only once per calendar day even if multiple sessions exist.
- Count alongside a Norwy session on the same day as one active day.
- Mark the corresponding Home weekly activity indicator active.
- Use `phasesEnded = 1` and `skipCount = 0` so the existing status logic treats the session as completed/good.

Manual sessions must not affect:

- Fitness level.
- Recommended workout.
- Norwy workout progression.
- Norwy completion statistics.
- Built-in workout state.

`isManual`, not `phasesEnded` or `duration`, is the authoritative discriminator.

### 1.8 LogActivity visibility

The feature adds the top-bar action and form only. It does not add a manual-workout list, manual-workout cards, edit controls, or delete controls.

The existing LogActivity display behavior should remain unchanged. Manual entries are stored silently and are not surfaced by this feature.

If the current screen already renders every `Session` row, verify that the implementation does not unintentionally expose manual rows; resolve that narrowly at the ViewModel/query boundary rather than redesigning the screen.

### 1.9 Analytics

After a successful database insert, emit:

```text
manual_workout_logged
```

The event has no parameters.

Do not emit it for validation errors, dismissals, failed inserts, loading-state transitions, or duplicate taps.

## 5. Cross-cutting pitfalls

- Verify the active Room schema version before selecting a migration number.
- Preserve the previous exported schema artifact.
- Update every `Session` constructor and fake after adding non-null fields.
- Do not use an upsert for manual entries; duplicates on the same date are allowed.
- Do not use `phasesEnded`, `skipCount`, `name`, or `duration` to identify manual rows; use `isManual`.
- Do not let manual rows participate in Norwy progression.
- Do not disable Save for invalid input; Save must expose errors.
- Do not clear form state before the database operation completes.
- Do not close the sheet from a `finally` block after a failed save.
- Do not emit analytics before persistence succeeds.
- Update all `Analytics` implementations and fakes.
- Store the translated name text supplied at save time, not a resource ID.
- Keep the type list order explicit; do not depend on enum sorting or localization order.
- Treat `24:00` as valid and `24:01` as invalid.
- Validate date bounds in the domain/ViewModel as well as in the date picker.
- Avoid using emoji or localized full labels as the only UI test selectors.
- Keep locale resource keys identical across all supported locales.
- Do not introduce edit/delete or visible manual-history UI in this iteration.
- Preserve unrelated working-tree changes and stage only files belonging to the current chunk.
